# 종목 상세 읽는 법 검증 범위

이슈 #493의 안내를 PR #500이 반영된 종목 상세에서 검증한다. 말풍선의 위치와 배경 명암, 탭 이동, 방문 기록이 대상이다. 문구의 학습 효과는 자동 테스트의 검증 대상이 아니다.

## 화면 기준

- `한눈에 보기`가 첫 탭이다.
- 나머지 네 탭은 현재 성향의 `cardOrder`를 따른다. 이름은 `모델이 본 이유`, `누가 사고팔았나`, `시장 분위기`, `회사 상태`다.
- 개인 확인 사항은 탭과 별개로 유지된다.
- 첫 방문 초대는 준비가 끝난 로그인 또는 데모 사용자에게 보인다. 일반 방문자는 공개 종목의 `읽는 법`이나 이용 안내의 다시 보기로 시작한다.
- 안내는 이용자가 시작한다. 안내를 닫으면 현재 종목을 계속 볼 수 있다.
- 말풍선 문구는 단계 데이터에서 관리한다. 수치는 강조된 화면에서 확인하고, 안내는 그 수치를 읽는 방법을 설명한다.
- 탭 소개는 그 탭을 열 상황과 확인할 질문을 설명한다. 주요 확인 사항은 데이터를 보는 이유, 비교 기준, 변화의 해석을 설명한다.
- 읽는 순서에는 실제로 반영한 투자 유형을 표시한다. 진단 자료가 없는 방문자나 예시 성향으로 대체된 화면에는 개인 진단 결과라고 설명하지 않는다.

안내는 읽는 순서를 한 번 설명한 뒤 각 탭의 소개와 상세 설명을 이어서 보여 준다. 한 탭에서 용도, 주요 숫자, 비교 방법을 확인하고 다음 탭의 소개로 이동한다. 탭 순서는 현재 성향의 배치를 따른다. 별도의 중간 전환 안내는 표시하지 않는다.

## 자동 테스트

| 구간 | 행동 | 관찰할 결과 |
|---|---|---|
| 시작 전 | 로그인 또는 데모 상태로 종목 상세를 처음 연다 | 시작 안내와 다시 보기 동작을 찾을 수 있다. 배경을 자동으로 막지 않는다 |
| 시작 | 안내를 시작한다 | 현재 설명, 강조 대상, 다음 버튼이 함께 보인다 |
| 안내 구성 | 처음부터 진행한다 | 읽는 순서 뒤에 첫 탭 소개와 해당 탭의 상세 설명이 이어진다. 다른 탭도 소개와 상세 설명을 한 묶음으로 진행한다 |
| 진행 표시 | 소개와 상세 설명을 넘기고 이전 단계로 돌아간다 | 현재 탭 이름과 소개를 포함한 탭 안의 순서 및 전체 단계 수를 표시한다. 범위가 있는 한눈에 보기는 1/4부터 4/4까지 표시한다. 다음 탭 소개는 1부터 시작한다 |
| 읽는 순서 | 좁은 화면에서 순서 설명을 본다 | 이 단계에서만 다섯 탭을 여러 줄로 보여 준다. 다음 단계나 닫기 후 원래 탭 배치로 돌아온다 |
| 닫기 표시 | 말풍선 오른쪽 위를 본다 | 글자 대신 X 아이콘을 표시한다. 접근성 이름은 `안내 닫기`다 |
| 이동 버튼 | 이전과 다음을 본다 | 보이는 높이는 얇게 줄이고 누르는 영역은 44px 이상으로 유지한다 |
| 탭 이동 | 다음과 이전을 누른다 | 현재 성향의 탭 순서를 따른다. 한 탭의 마지막 상세 설명 다음에 다음 탭 소개가 나온다. 여기서 이전을 누르면 앞 탭의 마지막 상세 설명으로 돌아간다 |
| 준비 대기 | 조건부로 렌더링되는 탭으로 이동한다 | 대상이 나타난 뒤 강조한다. 이전 패널의 잘못된 위치를 강조하지 않는다 |
| 중단 | 닫기 또는 Escape를 누른다 | 말풍선과 배경 명암이 사라진다. 시작한 버튼으로 포커스가 돌아온다. 초대가 사라졌으면 `읽는 법`으로 돌아가고 화면을 조작할 수 있다 |
| 키보드 | Tab과 Shift+Tab을 누른다 | 포커스가 안내 안에서 순환한다. 한 번의 입력으로 두 단계가 이동하지 않는다 |
| 다시 보기 | 안내를 다시 시작한다 | 첫 단계에서 시작한다. 기존 오버레이가 중복되지 않는다 |
| 완료 | 마지막 단계를 완료한다 | 완료 상태를 저장한다. 중간에 닫은 기록과 구분한다 |
| 후속 힌트 | 완료한 종목 외의 종목을 차례로 연다 | 서로 다른 다음 두 종목에만 작은 힌트가 보인다. 같은 종목 재방문은 횟수를 추가로 쓰지 않는다 |
| 저장 실패 | 저장 값이 깨졌거나 저장소 접근이 거부된다 | 화면과 안내를 계속 사용할 수 있다 |
| 계정 구분 | 일반 방문자, 데모, 로그인 계정을 바꾼다 | 안내 기록을 서로의 기록으로 취급하지 않는다 |
| 이용 안내 | 로그인 없이 이용 안내의 다시 보기로 들어간다 | 공개 종목 화면에서 안내가 시작한다 |
| 화면 이탈 | 안내 중 다른 종목이나 경로로 이동한다 | 이전 설명, 오버레이, 키보드 잠금이 남지 않는다 |
| 자료 없음 | 모델 또는 근거가 없는 종목을 연다 | 없는 숫자를 만들어 설명하지 않는다. 보이는 요약 또는 자료 없음 설명을 가리킨다 |
| 문구와 강조 대상 | 히스토그램, 가격 흐름 분위기, 뉴스 그래프와 재무 안내를 읽는다 | 보이는 항목을 강조하고 각 그래프의 축과 재무 주제를 해석하는 방법을 안내한다 |
| 변화 해석 | 수급과 재무 지표의 안내를 읽는다 | 수급은 자료가 여러 날일 때만 기간 합계와 마지막 날을 비교한다. 재무는 지표 설명과 매출·이익, 자산·빚, 주가 비교로 이어진다 |
| 좁은 화면 | 320px과 390px에서 진행한다 | 말풍선과 버튼이 화면 안에 들어오고 가로 스크롤을 만들지 않는다 |
| 긴 설명 | 작은 화면에서 수급과 재무의 확인 사항을 읽는다 | 말풍선이 화면 안에 들어오고 함께 표시할 공간이 있는 강조 대상을 가리지 않는다 |
| 화면 크기 전환 | 데스크톱에서 안내를 시작한 뒤 모바일 폭으로 바꾼다 | 현재 강조 대상과 말풍선이 화면 안에 보인다 |
| 동작 줄이기 | reduced motion 설정으로 시작한다 | 이동 효과 없이 진행하고 모든 동작을 사용할 수 있다 |

문구와 방문 기록은 단위 테스트로 확인한다. 브라우저 테스트는 보이는 역할과 버튼 이름을 우선 사용한다. 강조 대상 연결에만 `data-reading-target`을 쓴다. CSS 순서나 `nth-child`로 탭을 찾지 않는다.

## 기존 화면 회귀

`calculation-basis.spec.ts`는 개인화 순서, 주가 차트, 개인 확인 사항, 320px부터 데스크톱까지의 배치, 재무 묶음과 공시를 검증한다. 읽는 법 테스트를 추가해도 이 기준을 유지한다.

`onboarding.spec.ts`와 종목 메모 테스트는 데모 진입과 기존 저장 동작을 검증한다. 읽는 법 안내는 가입, 설문, 보유 종목 입력을 대신하지 않는다.

## 테스트 데이터

브라우저 테스트는 `supabase-stub.mjs`의 가짜 응답과 데모 세션을 사용한다. 운영 DB와 실제 계정의 보유 종목을 사용하지 않는다. 기준 종목 코드는 `000660`이다. 자료 없음은 테스트의 요청 대체로 만든다.

새 레이아웃의 기준 검사는 안내 구현 전에 통과했다. 이 문서의 목록은 검증 범위이며, 목록 자체가 개별 테스트의 통과 기록은 아니다. 최종 결과는 실제 실행 결과와 함께 보고한다.

## 실행 명령

`frontend/`에서 저장소에 고정된 pnpm 10.33.0으로 실행한다. 다른 버전이 기본으로 설치되어 있으면 `pnpm dlx pnpm@10.33.0` 뒤에 같은 명령을 붙인다.

```sh
pnpm test:unit
pnpm exec playwright test tests/e2e/reading-tour.spec.ts tests/e2e/calculation-basis.spec.ts tests/e2e/onboarding.spec.ts tests/e2e/marks.spec.ts
pnpm build
```

Playwright의 기본 설정은 테스트 전용 Supabase 스텁과 로컬 웹 서버를 띄운다. 브라우저 실행 파일을 별도로 지정한 임시 설정은 저장소에 커밋하지 않는다. 기본 `pnpm build`와 `next build --webpack`의 결과는 구분한다.

## 화면 확인

배경이 약하게 어두워지고, 설명 대상만 밝게 남는지 확인한다. 다음 단계에서는 새 대상 가까이로 말풍선이 옮겨야 한다. 상단 고정 헤더, 긴 설명, 작은 화면에서도 강조 영역과 버튼이 가려지지 않는지 확인한다.

화면 확인에는 테스트 서버의 가짜 데이터를 사용한다. 스크린샷에 실제 계좌나 실제 보유 정보를 넣지 않는다.

## 문구의 근거

화면의 수급, 모델 막대와 뉴스 집계는 각 패널의 실제 계산 정의를 따른다. 재무 지표의 의미와 업종별 비교의 주의점은 [SEC의 재무제표 입문 안내](https://www.sec.gov/investor/pubs/begfinstmtguide.htm)를 참고했다. 이 서비스의 재무 비교에는 해당 지표를 계산할 수 있는 여러 업종의 코스피 회사 자료를 사용한다. 같은 업종만 모은 값이 아니다.

`frontend/`에서 저장소에 고정된 pnpm 10.33.0으로 실행했다.

```sh
pnpm dlx pnpm@10.33.0 test:unit
pnpm dlx pnpm@10.33.0 lint

NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=e2e-anon-key NEXT_PUBLIC_CHART_LOCAL_PREVIEW=0 pnpm dlx pnpm@10.33.0 build
git diff --check HEAD
```

단위 테스트 218개, 브라우저 테스트 15개와 린트가 통과했다. 브라우저 검사에는 안내 13개와 기존 상세 화면 회귀 2개가 포함됐다. 기본 Turbopack 빌드도 통과했고 백테스트 API의 파일 추적 경고 2건이 표시됐다. `git diff --check HEAD`는 통과했다.

브라우저 검사는 두 성향의 읽는 순서와 각 탭의 소개 직후 해당 탭의 상세 설명이 이어지는 흐름을 확인한다. 탭 소개를 포함해 진행 숫자를 계산한다. 범위가 있는 한눈에 보기는 1/4부터 4/4까지 표시하고, 자료가 없는 경우는 소개와 자료 없음 설명을 1/2 및 2/2로 표시한다. 다음 탭 소개에서 이전을 누르면 앞 탭의 마지막 상세 설명으로 돌아간다. 일반 방문자에게는 성향 진단 후 순서가 달라질 수 있다고 설명한다.

320px, 390px, 1280px과 안내 중 화면 크기 변경을 검사했다. 320px 및 1280px에서는 한눈에 보기, 수급, 모델, 재무 안내가 강조 대상을 가리지 않는지도 확인했다. 실제 진단 자료가 없는 이전 프로필이 예시 성향을 자기 진단 결과로 안내하지 않는 경우도 검사했다.

부모 작업은 최종 빌드의 320px 화면에서 읽는 순서가 먼저 나오는지 확인했다. 한눈에 보기 소개 1/4 뒤 상세 설명이 2/4부터 4/4까지 이어졌고, 다음은 수급 소개 1/3이었다. 이전 버튼을 누르면 한눈에 보기 4/4로 복귀했다. 다시 다음으로 진행하면 수급 소개 1/3과 상세 설명 2/3이 이어졌다. X로 닫은 뒤 오버레이가 사라지고 포커스가 `읽는 법`으로 돌아왔다. 임시 화면 크기는 확인 후 해제했다.

과거 사례의 선정 기준은 차트 서빙의 실제 분포 생성 정의를 따른다. 새 차트 자료에서는 상승 점수와 평소 가격 흔들림이 가까운 과거 종목 및 거래일을 선택하고, 선택한 예측 기간의 종가 변화를 사용한다. 구형 자료에는 이 선정 기준을 단정하지 않는다. 범위와 모델 탭의 수익률 분포는 같은 스냅샷을 사용한다.

실제 수정과 이전 검증 기록은 로컬 결정 기록에 남겼다. 이 문서는 현재 구현의 검증 범위와 최종 실행 결과를 정리한다.


## 2026-11-27 UX 라이팅 검수

[UX 라이팅 가이드](../../UX_WRITING.md)의 존중, 이해, 정직함, 자율성을 기준으로 시작 안내, 다섯 탭의 소개와 상세 설명, 자료 없음 안내, 재무 지표 여섯 종류, 후속 힌트와 이용 안내의 진입 문구를 검수했다. 기존 오류 안내와 이동 버튼은 유지했다.

용어의 뜻과 확인 방법을 함께 설명하고, 제목의 마침표를 없앴다. 순매수의 합계와 마지막 하루, 재무 비교 기간, 과거 사례의 선정 기준은 유지했다. 뉴스의 집계 기준을 수집 시각으로 단정하지 않고, 코스피 중간값을 전체 상장사의 값으로 설명하지 않도록 고쳤다. 과거 수익률 범위는 실제 사례가 정확히 해당 비율만큼 포함된다고 단정하지 않는다. 자료가 없을 때는 기사나 공시가 있다고 안내하지 않는다.

실행한 명령은 다음과 같다. 단위 테스트는 저장소 루트에서, 린트와 브라우저 테스트 및 빌드는 `frontend/`에서 실행했다.

```sh

pnpm dlx pnpm@10.33.0 lint

NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=e2e-anon-key NEXT_PUBLIC_CHART_LOCAL_PREVIEW=0 pnpm dlx pnpm@10.33.0 build
git diff --check
```

단위 테스트 218개, 브라우저 테스트 15개, 린트와 기본 Turbopack 빌드가 통과했다. 빌드에서는 기존 백테스트 API 파일 추적 경고 2건이 표시됐다. `git diff --check`도 통과했다.

브라우저 테스트는 개발 서버에서 실행했다. `CI=1` 실행은 기존 Supabase 스텁의 54321 포트 점유로 시작하지 못해, 기존 스텁을 재사용하는 기본 설정으로 실행했다. 320px, 390px, 1280px에서 안내 이동과 말풍선 배치를 검사했다. 320px 수급, 재무, 모델 막대 안내의 스크린샷에서도 문구와 이동 버튼이 화면 안에 보이는지 확인했다.

실제 초보 투자자의 이해도는 아직 검증하지 않았다. 다음 사용자 검증에서는 안내를 읽은 사람이 지표의 뜻과 확인 방법을 자기 말로 설명하고 다른 종목에도 적용할 수 있는지 확인한다.


### 같은 날 읽는 상황과 방법 중심으로 재검수

사용자 피드백에 따라 탭 소개는 언제, 왜 보는지 설명하고, 상세 안내는 무엇을 어떻게 비교할지 안내하도록 수정했다. UX 라이팅 가이드의 '이해' 원칙과 예시에도 같은 기준을 반영했다. 정의와 계산식은 기존 용어 설명과 계산 근거에서 다루며, 튜토리얼에는 부호와 비교 대상처럼 화면을 읽는 데 필요한 뜻을 남겼다.

뉴스 그래프에서는 점을 눌러 해당 시점의 분위기를 확인하고 기사가 적다는 표시가 나오면 참고로 보도록 안내한다. 선택한 시점과 대표 기사 목록이 연결되어 있다고 설명하지 않는다. 재무 비교는 보고서 기간을 기준으로 하며, 순매수의 +와 −는 산 수량과 판 수량의 관계로 읽도록 안내한다. 과거 사례는 같은 신호라고 단정하지 않는다.

`frontend/`에서 다음 명령을 실행했다.

```sh
pnpm dlx pnpm@10.33.0 test:unit
pnpm dlx pnpm@10.33.0 lint
PLAYWRIGHT_BROWSERS_PATH=/private/tmp/market-tip-playwright pnpm dlx pnpm@10.33.0 test:e2e reading-tour.spec.ts calculation-basis.spec.ts --reporter=list,html
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 NEXT_PUBLIC_SUPABASE_ANON_KEY=e2e-anon-key NEXT_PUBLIC_CHART_LOCAL_PREVIEW=0 pnpm dlx pnpm@10.33.0 build
git diff --check
```

최종 단위 테스트 218개, 브라우저 테스트 15개, 린트와 빌드가 통과했다. 첫 브라우저 실행에서는 이전 수급 문구를 기대하던 검사 2개가 실패했다. 같은 기간의 순매수 합계라는 의미를 유지해 기대 문구를 갱신한 뒤 전체 15개를 다시 통과했다. 기존 백테스트 API 파일 추적 경고 2건은 남아 있다.

320px의 수급, 재무, 과거 사례 안내 스크린샷에서 설명과 이동 버튼을 확인했다. 실제 초보자가 언제, 왜 항목을 보는지 설명하고 비교할 곳을 찾을 수 있는지는 사용자 검증이 필요하다.
