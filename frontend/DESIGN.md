# DESIGN.md v2 — 화면 규칙

> **한 화면에서 색이 있는 것은 가격 방향과 초록 버튼 하나가 전부다.**

값(색·글자 크기·모서리·그림자)의 SSOT는 **`app/globals.css`의 `@theme`** 다. 이 문서는 토큰이 표현하지 못하는
**판단 규칙**만 둔다. 차트 라이브러리에 넘기는 색만 `lib/chart-colors.ts`에 리터럴로 중복된다(이유는 그 파일 맨 위).

우선순위: `AGENTS.md` > 이 문서 > 디자인 스킬(`.claude/skills/`). 톤은 애플 웹처럼 절제된 쪽이다 —
강조하고 싶으면 색을 더하지 말고 주변을 덜어낸다.

## 화면 규칙 v2 (2026-10-18)

사용자 피드백 "통일성 부족, 선·상자·펼치기·ⓘ 과다, 줄간격 들쑥날쑥, 페이지마다 정렬이 다름, 가운데 점 금지, AI 느낌 금지"를
판단 기준으로 먼저 정한다. **아래 규칙이 이 문서의 다른 항목과 부딪히면 v2가 이긴다**(바뀐 옛 항목은 표 맨 아래).

| 영역 | 규칙 | 이유·근거 |
|---|---|---|
| 정렬 | 모든 페이지의 본문 왼쪽 끝 = 헤더 로고 왼쪽 끝. 컨테이너 폭은 하나(헤더와 같은 1200px). 글을 읽는 페이지(성향·보유·성적표·진단·상세 본문)는 **왼쪽 정렬은 그대로 두고 본문 폭만** 좁힌다(최대 720px) | 페이지마다 가운데 정렬 폭이 달라(720·800·880·960) 시작선이 196~352px로 흩어졌다. 한 시작선은 F형 읽기(왼쪽 위부터 훑음)를 돕는다 [1] |
| 화면 구간 | 1024px 이상은 2단(8:4), 미만은 1단 | 태블릿 폭에서 2단이 좁아 카드가 눌렸다. 1단 순서 = 2단에서 왼쪽 → 오른쪽 |
| 글자 | **4단계만**: 페이지 제목 28 · 섹션 제목 20 · 본문 16 · 보조 13(흐린 색). 예외는 화면의 대표 수치 하나(가격 40) | 11종(11~40px)이 섞여 들쑥날쑥해 보였다. 단계를 줄이면 선택지가 줄어 일관성이 생긴다 [4] |
| 간격 | 블록 안 8 · 블록 사이 24 · 섹션 사이 48. 펼친 뒤에도 같은 간격 | 묶음 사이 간격이 묶음 안 간격보다 분명히 커야 선 없이 묶음이 보인다(근접의 원리) [2] |
| 선 | **눌러서 들어가는 목록의 행 사이에만**. 나머지는 간격으로 나눈다 | "선 대신 여백으로 묶는다", 선은 표·편집 영역처럼 경계가 꼭 필요한 곳의 마지막 수단 [2] |
| 상자 | 카드 단위로만. 카드 안 회색 상자·칩 상자 금지(값은 글자로) | 상자 안 상자가 41곳(상세)까지 쌓여 시선이 갈 곳을 잃었다 |
| 펼치기 | 기본은 다 보여 준다. 항목이 많을 때만 처음 3개 + "더 보기(N)". 뉴스·공시 등 목록은 같은 방식. **펼침 안 펼침 금지** | 숨긴 내용은 덜 보인다 — 중요한 건 숨기지 않는다. 아코디언은 일부만 필요한 긴 내용에만 맞다 [3] |
| 펼치기 예외 | **계산 근거는 블록마다 맨 아래 접기 하나, 이름은 '계산 근거'.** 접기 안에 또 접기는 두지 않는다. 결론, 근거 숫자와 비교 기준, 용어 정의(ⓘ)는 늘 펼쳐 둔다(2026-10-20, #372) | 계산식과 원자료는 일부 사람만 필요한 긴 내용이라 접기에 맞다 [3]. 이름과 자리가 같으면 어디서나 같은 곳을 찾는다 |
| ⓘ | 용어 정의(두 문장 이하)만, **누르면 열림**(키보드 Enter·Esc). "자세히" 글자 버튼은 모두 ⓘ로. 짧고 꼭 필요한 설명은 본문에 바로 | 정의 툴팁은 클릭·포커스로 열어야 키보드·터치 사용자도 쓴다. 꼭 필요한 정보를 툴팁에만 두지 않는다 [5] |
| 구분 기호 | **가운데 점(·) 금지**. 간격 또는 쉼표 | 사용자 피드백(AI 느낌). `copy-rules.ts`로 막는다 |
| 탐색 | 같은 목적지로 가는 길은 하나(상단 메뉴). "대시보드로 돌아가기"·"편집" 같은 중복 링크는 빈 상태 안내 버튼일 때만 | 같은 곳으로 가는 길이 여럿이면 고를 것만 늘어난다(힉의 법칙, `ux-scrap-guidelines`) |
| 개발 표시 | "모델 검증 전" 같은 개발 상태 표시는 화면에서 뺀다. 데모의 "예시 데이터"는 상단 데모 띠 한 곳에만 | '참고 정보·틀릴 수 있음'은 맨 아래 면책 문구가 말한다. 같은 말 반복 금지 |

**출처와 우리 규칙이 다른 점**
- [1]은 F형 읽기를 "규칙이 아니라 경향"으로 본다 → 우리는 시작선 하나만 정하고, 중요한 것을 무조건 왼쪽 위에 몰지는 않는다(대시보드는 왼쪽 내 것, 오른쪽 시장 전체).
- [3]의 디자인 시스템들은 "모두 펼치기" 버튼을 권하지만, 우리 목록은 짧아 "더 보기(N)" 하나로 충분하다(버튼 수를 늘리지 않는다).
- [4]는 8pt 격자(8·16·24)를 권한다 → 기존 4px 배수 규칙을 유지하되 블록·섹션 간격은 8·24·48 세 값만 쓴다.
- [5]의 Carbon은 hover로도 열리게 허용하지만, 우리는 누를 때만 연다(아래 2-3 "열고 닫기는 누를 때만", 보유 맵 팝업만 예외).

**v2로 바뀐 옛 항목**: 2장 타이포(18·20·14px 단계 → 4단계로 합침), 2-2 "카드 안 요소 간격 16px"(→ 블록 안 8), 2-3 "모델 검증 전은 신호가 처음 나오는 곳에 한 번"(→ 표시 안 함), 보유 히트맵 범례의 검증 상태 표시(→ 삭제).

### 읽는 순서 (2026-10-20, 지도교수 피드백 "어떤 순서로 봐야 할지 모르겠다")

| 규칙 | 적용 |
|---|---|
| 화면은 **결론 → 나에게 해당하는 것 → 둘러볼 것** 순서 | 대시보드: 요약 문장 → 성향 한 줄 → 내 포트폴리오 → 어제와 달라진 근거 → 신호가 강한 종목 |
| 2단(1024px 이상)은 **왼쪽이 '내 것', 오른쪽이 '둘러보기'**. 1단은 왼쪽 → 오른쪽 순서 그대로 | 두 열의 제목 줄은 같은 높이(44px)에서 시작한다 |
| **컨트롤은 그것이 바꾸는 내용의 제목 줄**에 둔다. 설명은 ⓘ 대신 제목 아래 13px 한 줄을 늘 둔다(바꿔도 아래 내용이 흔들리지 않게 한 줄 고정) | 대시보드 기간 전환은 '내 포트폴리오' 제목 오른쪽, 오른쪽 목록 제목 아래 'N주 기준' |
| **행동 버튼은 읽는 흐름의 끝**(그 블록 아래)에 둔다 | 저장, 다시 진단, 목록에 넣기 |

- 예외: 종목 상세의 관심 종목, 메모 버튼과 보유 정보는 헤더 쪽에 둔다(10/20 사용자 결정, #376).

### 용어 설명 단계 (2026-10-20, #372)

숫자 하나는 네 단계로 읽힌다: **결론 한 문장 → 근거 숫자와 비교 기준 → 용어 정의(ⓘ) → 계산 근거(접기)**.

| 자리 | 규칙 | 예 |
|---|---|---|
| 라벨 | 쉬운 이름 + 약어 괄호. 라벨 안에 긴 괄호 설명을 쓰지 않는다 | 이익 대비 주가(PER), 순자산 대비 주가(PBR), 자기자본 수익률(ROE), 영업이익률, 부채비율, 매출 증가율 |
| 값 아래 13px | 비교 기준 한 줄. **높아요, 낮아요, 비슷해요**까지만 쓴다. 저평가, 고평가, 싸다, 비싸다는 판정이라 쓰지 않는다(`copy-rules.ts`가 막는다) | "코스피 중간값 11.2배보다 높아요." 계산할 수 없으면 "적자라 계산하지 않아요." |
| ⓘ | 정의 한 문장 + 읽는 법 한 문장. 약어와 전문 용어에만 단다. 매출, 영업이익처럼 일상어에 가까운 말은 ⓘ 없이 | "주가가 회사 1년 이익의 몇 배인지예요. 업종마다 보통 수준이 달라…" |
| 계산 근거 | 블록 맨 아래 '계산 근거' 접기 하나(위 펼치기 예외) | 식, 원자료, 비교 기준을 만든 방법 |

- 용어 문장은 `lib/copy-glossary.ts`의 `TERM_INFO` 한 곳에 모으고, 화면은 `TermLabel`(`app/components/term-tip.tsx`)로 그린다. 모든 용어에 쉬운 이름, 정의, 읽는 법이 있는지 `copy-rules.test.ts`가 검사한다.
- 재무 비교 기준: DB에 업종 분류가 있고 같은 업종이 10개사 이상이면 업종 중간값, 아니면 코스피 중간값. 어느 기준인지 글자로 적는다. 중간값은 배치(`backend/analysis/text/value_pipeline/kospi_medians.py` → `lib/financial-medians.json`)로 미리 계산하고 화면에서 계산하지 않는다. 지금은 업종 분류가 없어 코스피 중간값이다.
- 판단 근거 네 탭은 같은 모양이다: 질문형 제목 → 결론 → 숫자와 비교 기준 → "왜 봐야 하나요?" 한 줄(무엇과 견줘 볼지) → 계산 근거.

## 0. 공통 원칙 (2026-09 사용자 피드백)

- **글자는 줄이고, 설명이 꼭 필요한 곳에만 한 줄.** 섹션 제목은 한 줄이고, 부제·eyebrow 라벨은 기본적으로 없다.
  남기는 것은 비교 기준·식별 정보(종목 코드·시장, 기준 모델, 합계)처럼 숫자를 읽는 데 필요한 것뿐이다.
- **앞으로 가는 주 버튼은 오른쪽 아래, 뒤로 가는 버튼은 왼쪽 아래.** 한 흐름 안의 버튼은 높이·가로 여백·글자 크기가 같다
  (`app/components/step-nav.tsx`). 라벨은 "다음"·"완료"·"저장하고 시작"처럼 행동만 쓰고 목적지를 붙이지 않는다.
- **문장 끝 규칙.** 보조 설명이 문장이면 "~요."로 끝내고 마침표를 찍는다. 제목·버튼·라벨·짧은 구(" · "로 잇는 값 포함)는 마침표 없이 쓴다(2026-10-18, `copy-rules.test.ts`가 `copy-glossary.ts` 문장을 검사).
- **같은 대상은 한 이름.** 보유 주식을 입력하는 곳은 '보유 종목'(상단 메뉴, 보유 종목 화면, 온보딩 보유 단계), 보는 곳은 '내 포트폴리오'(대시보드 섹션)다. '내 종목'은 쓰지 않는다(2026-10-20).
- **실데이터가 기본이다.** "실데이터" 표시는 하지 않고, 예시 값에만 "예시" 표시를 단다(`copy-rules.ts`가 검사). 출처·기준일은 그대로 둔다.

## 0-1. 보편 UX 체크리스트

1. 누르는 것은 44px 이상(문장 안 글자 링크·세그먼트 탭 제외, `tests/e2e/tap-targets.spec.ts`가 검사)
2. 글자 대비 4.5:1, 아이콘·테두리 3:1 이상
3. 주 버튼은 오른쪽, 취소·뒤로는 왼쪽, 한 화면에 주 버튼 하나
4. 되돌리기 어려운 행동(지우기·데모 로그아웃·삭제)은 확인 창 또는 되돌리기를 준다
5. 누르면 반응이 보인다(눌림·로딩·완료)
6. 오류 문구 = 무슨 일 + 어떻게 하면 되는지("…하지 못했어요. 잠시 뒤 다시 눌러 주세요.")
7. 같은 역할은 같은 컴포넌트, 새 화면은 기존 컴포넌트부터
8. 한 줄은 한글 약 40자 안팎(긴 문장은 `max-w-2xl`)

이 목록과 DESIGN.md 규칙 밖의 것(배치·정보 모양·강조·시각 실험)은 규칙으로 정하지 않는다.
새 화면은 시안을 2~3개 만들어 비교하고 사용자 피드백으로 정한다.

| `page` · `surface` · `track` · `line` | #f5f5f7 · #fff · #e8e8ed · #d2d2d7 | 페이지 · 흰 면 · 막대 바탕 · 구분선 | |

- **빨강은 실패 메시지 전용 · 목록에서 삭제하는 버튼은 회색 '삭제'**(`.btn-remove`).

- 브랜드 마크는 진녹·연두만 쓰며, '색은 가격 방향과 초록 버튼뿐' 규칙의 유일한 예외다(`docs/brand/README.md`, `--color-logo-*`).
- **범주색은 없다.** 투자자·지표·실험 런처럼 순서 없는 범주는 색이 아니라 **라벨과 위치**로 구분한다.
  - 수급: 투자자별 작은 막대 한 줄씩(순매수 적, 순매도 청)
  - 기여도: 가운데 0 기준 부호 막대(적 = 오르는 쪽으로 기여, 청 = 내리는 쪽)
  - 모델 성적표 개선/저하: 무채색 + ▲▼ + 단어
- **"예시 데이터" 표시는 조용한 회색 한 줄**이다. 실데이터에는 아무 표시도 달지 않는다. 주황(주의)과 뜻이 섞이지 않게 점을 붙이지 않는다.
- 주가 실선처럼 신호가 아닌 사실은 무채색(`CHART.priceLine`)이다.
- 시장 바의 흔들림·거래 낮음/보통/높음은 점 색으로 단계를 보인다: 회색(`ghost`) → 노랑(`caution-soft`) → 주황(`caution-mark`). 글자는 본문색. 빨강·파랑은 상승·하락 전용이라 쓰지 않는다.
- 모든 글자 색은 흰 배경과 `page` 위에서 4.5:1 이상이다(값 옆 주석에 대비를 적어 둔다).

- 임의 크기(`text-[13.5px]`) 금지. 모든 수치에 `tabular-nums`.

### 2-3. 출처·기준일·범례 (2026-10-09, 근거 `docs/research/source-display.md`)

- **기준일은 시장 바 ⓘ 설명의 맨 아래 줄에 한 번**(바에는 지수가 먼저, 10/20). 카드에는 날짜가 그와 다를 때만 적는다: 재무 보고서 시점, 뉴스 수집 시각, 2영업일 이상 밀린 데이터(`staleLabel`, 이때는 시장 바에도 경고).
- **출처는 페이지 맨 아래 한 묶음.** 상세는 "더 알아보기 › 데이터 출처·기준" 표, 대시보드는 따로 두지 않고 모델 성적표의 "데이터 출처" 묶음으로(맨 아래 면책 문구의 "모델 성적표"에서 간다, 2026-10-18). 카드마다 출처 버튼을 두지 않는다.
- **"모델 검증 전"은 모델 신호가 처음 나오는 곳에 한 번**(대시보드는 보유 맵 범례, 보유 종목이 없으면 신호 목록 아래).
- **색 범례는 점 + 단어**(`DotLegend`): 모델 신호 ● 상승 ● 중립 ● 하락(`SIGNAL_WORD`, 2026-10-18 '상방·하방'에서 변경), 뉴스 분위기 ● 긍정 ● 중립 ● 부정. 색 이름을 글자로 쓰지 않는다.
- **열고 닫기는 누를 때만.** 올리기(hover)·포커스로 열리는 창 금지. 누르면 열리고, 다시 누르기·바깥 누르기·Esc로 닫힌다. 열린 창 안에 또 접는 버튼을 두지 않는다.
- 보유 히트맵은 예외로 마우스 오른쪽 위에 정보 팝업을 표시한다. 키보드 포커스와 터치로도 같은 정보를 확인할 수 있어야 한다. 모든 칸은 높이 44px 이상·열 폭 30% 이상으로 그려 종목명을 늘 보인다(길면 말줄임). 칸 안에는 종목명(왼쪽 위)과 '평가금액 (비중)'(오른쪽 아래)만 쓰고 신호 단어는 쓰지 않는다(색과 범례가 말한다, 2026-10-20). 높이가 모자라면 한 줄에 나란히, 폭도 모자라면 이름만. 범례 줄에 '평가금액 (비중)'을 함께 적는다. 한 열 5칸(두 열 10칸)을 넘으면 작은 종목들을 "그 밖의 N종목" 칸 하나로 묶고, 누르면 맵 아래에 목록이 열린다. 맵 아래는 색 범례 한 줄만 두고(검증 상태·예시 표시는 같은 줄 끝 짧은 말), 설명 문장은 쓰지 않는다. '맞는다는 보장 없음'은 맨 아래 면책 문구가 말한다(2026-10-18, #326 후속·사용자 피드백).

### 2-1. 강조 계층 3단

| 단 | 무엇 | 모양 |
|---|---|---|
| 1단 | 판정 단어(하락·긍정적인 편·개인 등 그 카드의 결론) | `font-semibold` + 의미 색(상승·긍정 적, 하락·부정 청, 중립은 본문색) |
| 2단 | 핵심 숫자(가격·재무 비율·금액 등 수준 값) | `font-semibold` + 본문색(`text-ink`). 증감 숫자는 아래 방향색 규칙 적용 |
| 3단 | 나머지 | 굵게 쓰지 않는다. 회색(`text-body` 본문 · `text-muted` 보조) |

- **카드당 1단은 하나.** 같은 카드에 판정이 둘이면 하나만 1단, 나머지는 3단으로 내린다.
- **증감 숫자**(등락률·순매수·평단 대비·수익률 범위 끝값)는 상승 적(`--color-up`), 하락 청(`--color-down`), 표시 자릿수로 반올림해 0이면 본문색(`--color-body`)으로 둔다. ▲▼ 또는 부호(+/−)를 함께 표시하고, 0에는 방향 기호를 붙이지 않는다. 수급 행의 합계와 최근 거래일 숫자도 각 값의 방향색을 쓴다.
- **수준 값**(가격·재무 비율·가격 흔들림)은 본문색이다. 사용자 요청에 따라 재무 상태 탭의 모든 지표(매출 증가율 포함)는 무채색을 유지한다. 모델 성적표의 개선·저하도 기존 무채색 + ▲▼ + 단어 규칙을 유지한다.
- 수익률 분포의 **축 눈금은 보조색(`--color-muted`)**이다. 축과 구분되는 범위 끝값·선택한 구간 값에만 위 증감 방향색을 적용한다.

## 3. 간격·모서리·면

- **테두리 대신 면으로 구분한다.** 페이지 `#f5f5f7` 위에 흰 면(`.surface`), 모서리 `rounded-lg`(18px).
- 모서리: `sm` 8px(칩) · `md` 12px(버튼·입력) · `lg` 18px(면) · `xl` 20px(큰 면·시트).
- 그림자는 떠 있는 것(메뉴·시트·툴팁)에만. 가만히 있는 면에는 테두리도 그림자도 없다.
- 면 안 간격은 20~28px, 면 사이 24~32px. 구분은 여백 → 안쪽 구분선(`line-soft`) → 면 순서로 고른다.
- 본문 폭은 1200px 안에서.
- 누르는 것은 높이 44px 이상(`.btn-primary`·`.btn-secondary` 2.75rem). 세그먼트 탭만 예외로 36px(아이폰 세그먼트와 같은 크기).

## 4. 컴포넌트 규칙 (`globals.css` `@layer components`)

| 컴포넌트 | 클래스 | 규칙 |
|---|---|---|
| 기본 버튼 | `.btn-primary` | 초록. **화면에 하나.** 다음 행동 |
| 보조 버튼 | `.btn-secondary` | 회색 면. 기본 버튼 옆 대안 |
| 글자 버튼 | `.btn-text` | 초록 글자. 목록 안 이동·접기 |
| 묶음 목록 | `.group-list` | 아이폰 설정 같은 inset grouped. 흰 면 하나에 행을 쌓고 행 사이 안쪽 구분선 |
| 섹션 머리 | `.eyebrow` + 제목 | 작은 회색 라벨 위에 큰 제목 |
| 세그먼트 | `.segmented` | `role="tablist"` / `role="tab"` / `aria-selected`. 탭은 이것 하나 |
| 접기 | `details.disclosure` | 필수 정보는 지우지 않고 여기에 접는다. 한 줄 전체가 누르는 행(44px), 오른쪽에 `.count`(개수)와 화살표 |
| 빈 상태 | — | 한 문장 + 버튼 하나 |

- 헤더는 유리 막대(`.glass-bar`) 고정, 모든 화면이 공용 틀 `BrandHeader` 하나를 쓴다(로고 26px, 높이 56px, 위치가 같다. `tests/e2e/header.spec.ts`). 로그인 전 화면(로그인, 이용 안내, 오류)은 로고만, 로그인 뒤에는 이름 메뉴(보유 종목, 내 투자 성향, 이용 안내, 계정 설정, 로그아웃)를 붙인다.

  현재 화면은 옅은 렌즈 + 초록 글자. 상단 헤더에는 로고·계정·검색만 남긴다.

  도움말은 섹션마다 "왜 봐야 하나요?" 한 줄 한 곳.
- 출처는 숫자마다가 아니라 **섹션 단위 한 줄**(`SourceChip`).

## 4-1. 유리 층 (Liquid Glass)

애플 iOS 26의 Liquid Glass처럼 **콘텐츠 위에 떠서 움직이는 탐색 층에만** 유리를 쓴다.
데이터는 늘 불투명한 흰 면 위에 있다 — 숫자 뒤로 다른 숫자가 비치면 읽기가 무너진다.

| 쓰는 곳 | 클래스 |
|---|---|
| 상단 헤더, 설문 헤더 | `.glass-bar` (아래 선만) |
| 모바일 하단 탭 막대, 팝오버(계정 메뉴·시장 흔들림 설명) | `.glass` (안쪽 빛 테두리 + 윤곽 + 떠 있는 그림자) |

- 카드·목록·차트·모달 본문에는 쓰지 않는다. 한 화면에 떠 있는 유리는 두 겹을 넘지 않는다.
- 유리 위 글자도 4.5:1 이상. 흰 72% 위에서 `body` 이상 진한 글자만 쓴다.
- 글이 여러 줄인 팝오버(계정 메뉴·시장 흔들림 설명)는 뒤 글자가 비쳐 읽기 어려우므로 흰 90%(`glass bg-white/90`)로 짙게 한다.
- 설명 팝오버는 트리거 바로 아래에 붙는다. 마우스는 올리면·키보드는 포커스가 가면 보이고, 터치는 탭으로 열고 바깥 탭·Esc로 닫는다(`market-detail.tsx`). 헤더의 `backdrop-filter`가 `fixed`의 기준 상자가 되므로 헤더 안에서 띄우는 것은 body로 portal한다.
- `prefers-reduced-transparency`·`prefers-contrast: more`·흐림 미지원 브라우저는 불투명 흰 면으로 바뀐다(`globals.css`).
- 클레이모피즘(부푼 3D)·뉴모피즘은 쓰지 않는다. 장난감처럼 보여 금융 근거의 무게와 맞지 않고, 면 대비가 낮다.

## 5. 모션

- 150~200ms `ease-out`, **펼치기/닫기와 눌림 피드백에만.** 등장 애니메이션·스크롤 연동 없음.
- `transform`·`opacity`만 움직인다. `prefers-reduced-motion`은 `globals.css`에서 전역 처리.

## 6. 차트

- 격자 최소(가로 기준선 하나 정도), **범례 대신 직접 라벨**, 강조점 하나.
- 차트 하나가 질문 하나에 답한다. 두 질문이면 차트를 나눈다(작은 여러 개).

## 7. 이 프로젝트에만 있는 제약

`AGENTS.md`의 표현 규칙이 디자인보다 위다.

- 미래 주가 점선 곡선 금지. 확률 단정 금지.
- 모든 수치에 비교 기준·구간 말·출처가 붙는다. 정리한다고 빼지 않고 접는다.
- **하드 제약**(사용자가 직접 정한 것)은 주의 표시로 칠하지 않는다. 위험이 아니라 사용자의 선택이다.
- 재점검 신호 옆에는 매도 지시가 아니라는 표시가 늘 함께 간다.
- 화면 문구는 `lib/copy-glossary.ts`의 쉬운 말을 쓰고, 금지어는 `lib/copy-rules.ts`가 검사한다.

## 새 화면을 만들 때 점검

1. 이 화면이 답하는 질문 하나가 첫 화면(스크롤 전)에 있는가
