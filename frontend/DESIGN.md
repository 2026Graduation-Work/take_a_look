# DESIGN.md v2 — 화면 규칙

> **한 화면에서 색이 있는 것은 가격 방향과 초록 버튼 하나가 전부다.**

값(색·글자 크기·모서리·그림자)의 SSOT는 **`app/globals.css`의 `@theme`** 다. 이 문서는 토큰이 표현하지 못하는
**판단 규칙**만 둔다. 차트 라이브러리에 넘기는 색만 `lib/chart-colors.ts`에 리터럴로 중복된다(이유는 그 파일 맨 위).

우선순위: `AGENTS.md` > 이 문서 > 디자인 스킬(`.claude/skills/`). 톤은 애플 웹처럼 절제된 쪽이다 —
강조하고 싶으면 색을 더하지 말고 주변을 덜어낸다.

---

## 0. 공통 원칙 (2026-09 사용자 피드백)

- **글자는 줄이고, 설명이 꼭 필요한 곳에만 한 줄.** 섹션 제목은 한 줄이고, 부제·eyebrow 라벨은 기본적으로 없다.
  남기는 것은 비교 기준·식별 정보(종목 코드·시장, 기준 모델, 합계)처럼 숫자를 읽는 데 필요한 것뿐이다.
- **앞으로 가는 주 버튼은 오른쪽 아래, 뒤로 가는 버튼은 왼쪽 아래.** 한 흐름 안의 버튼은 높이·가로 여백·글자 크기가 같다
  (`app/components/step-nav.tsx`). 라벨은 "다음"·"완료"·"저장하고 시작"처럼 행동만 쓰고 목적지를 붙이지 않는다.
- **실데이터가 기본이다.** "실데이터" 표시는 하지 않고, 예시 값에만 "예시" 표시를 단다(`copy-rules.ts`가 검사). 출처·기준일은 그대로 둔다.

## 0-1. 보편 UX 체크리스트

1. 누르는 것은 44px 이상(문장 안 글자 링크·세그먼트 탭 제외, `tests/e2e/tap-targets.spec.ts`가 검사)
2. 글자 대비 4.5:1, 아이콘·테두리 3:1 이상
3. 주 버튼은 오른쪽, 취소·뒤로는 왼쪽, 한 화면에 주 버튼 하나
4. 되돌리기 어려운 행동(지우기·데모 로그아웃·삭제)은 확인 창 또는 되돌리기를 준다
5. 누르면 반응이 보인다(눌림·로딩·완료)
6. 오류 문구 = 무슨 일 + 어떻게 하면 되는지("…하지 못했어요. 잠시 뒤 다시 눌러 주세요.")
7. 같은 역할은 같은 컴포넌트, 새 화면은 기존 컴포넌트부터
8. 한 줄은 한글 약 40자 안팎(긴 문장은 `max-w-2xl`)

이 목록과 DESIGN.md 규칙 밖의 것(배치·정보 모양·강조·시각 실험)은 규칙으로 정하지 않는다.
새 화면은 시안을 2~3개 만들어 비교하고 사용자 피드백으로 정한다.

- **빨강은 실패 메시지 전용 · 목록에서 삭제하는 버튼은 회색 '삭제'**(`.btn-remove`).

- 브랜드 마크는 진녹·연두만 쓰며, '색은 가격 방향과 초록 버튼뿐' 규칙의 유일한 예외다(`docs/brand/README.md`, `--color-logo-*`).
- **범주색은 없다.** 투자자·지표·실험 런처럼 순서 없는 범주는 색이 아니라 **라벨과 위치**로 구분한다.
  - 수급: 투자자별 작은 막대 한 줄씩(순매수 적, 순매도 청)
  - 기여도: 가운데 0 기준 부호 막대(적 = 오르는 쪽으로 기여, 청 = 내리는 쪽)
  - 모델 성적표 개선/저하: 무채색 + ▲▼ + 단어
- **"예시 데이터" 표시는 조용한 회색 한 줄**이다. 실데이터에는 아무 표시도 달지 않는다. 주황(주의)과 뜻이 섞이지 않게 점을 붙이지 않는다.
- 주가 실선처럼 신호가 아닌 사실은 무채색(`CHART.priceLine`)이다.
- 시장 바의 흔들림·거래 낮음/보통/높음은 점 색으로 단계를 보인다: 회색(`ghost`) → 노랑(`caution-soft`) → 주황(`caution-mark`). 글자는 본문색. 빨강·파랑은 상승·하락 전용이라 쓰지 않는다.
- 모든 글자 색은 흰 배경과 `page` 위에서 4.5:1 이상이다(값 옆 주석에 대비를 적어 둔다).

## 2. 타이포 스케일

| 클래스 | 크기 | 쓰는 곳 |
|---|---|---|
| `text-2xs` | 13px | 각주, 차트 눈금. 이보다 작게 쓰지 않는다 |
| `text-xs` | 14px | 보조 글, 라벨 |
| `text-sm` | **16px** | **본문 기준** |
| `text-base` | 18px | 목록 항목 제목, 한 줄 결론 |
| `text-lg` | 20px | 카드 제목 |
| `text-xl` | 24px | 섹션 제목 |
| `text-3xl` | 28px | 화면 제목 |
| `text-4xl` | 40px | 화면의 대표 수치 하나 |

- 2026-09 피드백으로 한 단계 키웠다(본문 15→16px, 가장 작은 글자 12→13px). 글자를 키운 대신 **한 화면 정보량을 줄인다.**
- 굵기는 3단계: `font-normal` · `font-medium` · `font-semibold`. `font-bold` 이상 금지.
- 임의 크기(`text-[13.5px]`) 금지. 모든 수치에 `tabular-nums`.

### 2-3. 출처·기준일·범례 (2026-10-09, 근거 `docs/research/source-display.md`)

- **기준일은 시장 바에 한 번.** 카드에는 날짜가 그와 다를 때만 적는다: 재무 보고서 시점, 뉴스 수집 시각, 2영업일 이상 밀린 데이터(`staleLabel`).
- **출처는 페이지 맨 아래 한 묶음.** 상세는 "더 알아보기 › 데이터 출처·기준" 표, 대시보드는 하단 "데이터 출처·기준" 표(`SourceTable`). 카드마다 출처 버튼을 두지 않는다.
- **"모델 검증 전"은 모델 신호가 처음 나오는 곳에 한 번**(대시보드는 보유 맵 범례, 보유 종목이 없으면 신호 목록 아래).
- **색 범례는 점 + 단어**(`DotLegend`): 모델 신호 ● 상방 ● 중립 ● 하방, 뉴스 분위기 ● 긍정 ● 중립 ● 부정. 색 이름을 글자로 쓰지 않는다.
- **열고 닫기는 누를 때만.** 올리기(hover)·포커스로 열리는 창 금지. 누르면 열리고, 다시 누르기·바깥 누르기·Esc로 닫힌다. 열린 창 안에 또 접는 버튼을 두지 않는다.

### 2-1. 강조 계층 3단

| 단 | 무엇 | 모양 |
|---|---|---|
| 1단 | 판정 단어(하방·긍정적인 편·개인 등 그 카드의 결론) | `font-semibold` + 의미 색(상승·긍정 적, 하락·부정 청, 중립은 본문색) |
| 2단 | 핵심 숫자(범위·수익률·금액) | `font-semibold` + 본문색(`text-ink`) |
| 3단 | 나머지 | 굵게 쓰지 않는다. 회색(`text-body` 본문 · `text-muted` 보조) |

- **카드당 1단은 하나.** 같은 카드에 판정이 둘이면 하나만 1단, 나머지는 3단으로 내린다.
- 목록 행마다 붙는 방향은 막대·점이 색을 맡고, 글자는 2단·3단으로 둔다.

## 3. 간격·모서리·면

- **테두리 대신 면으로 구분한다.** 페이지 `#f5f5f7` 위에 흰 면(`.surface`), 모서리 `rounded-lg`(18px).
- 모서리: `sm` 8px(칩) · `md` 12px(버튼·입력) · `lg` 18px(면) · `xl` 20px(큰 면·시트).
- 그림자는 떠 있는 것(메뉴·시트·툴팁)에만. 가만히 있는 면에는 테두리도 그림자도 없다.
- 면 안 간격은 20~28px, 면 사이 24~32px. 구분은 여백 → 안쪽 구분선(`line-soft`) → 면 순서로 고른다.
- 본문 폭은 1200px 안에서.
- 누르는 것은 높이 44px 이상(`.btn-primary`·`.btn-secondary` 2.75rem). 세그먼트 탭만 예외로 36px(아이폰 세그먼트와 같은 크기).

## 4. 컴포넌트 규칙 (`globals.css` `@layer components`)

| 컴포넌트 | 클래스 | 규칙 |
|---|---|---|
| 기본 버튼 | `.btn-primary` | 초록. **화면에 하나.** 다음 행동 |
| 보조 버튼 | `.btn-secondary` | 회색 면. 기본 버튼 옆 대안 |
| 글자 버튼 | `.btn-text` | 초록 글자. 목록 안 이동·접기 |
| 묶음 목록 | `.group-list` | 아이폰 설정 같은 inset grouped. 흰 면 하나에 행을 쌓고 행 사이 안쪽 구분선 |
| 섹션 머리 | `.eyebrow` + 제목 | 작은 회색 라벨 위에 큰 제목 |
| 세그먼트 | `.segmented` | `role="tablist"` / `role="tab"` / `aria-selected`. 탭은 이것 하나 |
| 접기 | `details.disclosure` | 필수 정보는 지우지 않고 여기에 접는다. 한 줄 전체가 누르는 행(44px), 오른쪽에 `.count`(개수)와 화살표 |
| 빈 상태 | — | 한 문장 + 버튼 하나 |

- 헤더는 유리 막대(`.glass-bar`) 고정. 로고는 진녹 글자, 현재 위치는 연두 밑줄.
- **모바일(<640px) 주요 화면 이동은 하단 유리 탭 막대**(`.tab-bar.glass`)다. 엄지가 닿는 곳에 떠 있고,
  현재 화면은 옅은 렌즈 + 초록 글자. 상단 헤더에는 로고·계정·검색만 남긴다.
- 아이콘은 한 계열(선 굵기 1.5px 통일). **이모지 금지.** "i"·"?"·"!" 동그라미를 흩뿌리지 않는다 —
  도움말은 섹션마다 "왜 봐야 하나요?" 한 줄 한 곳.
- 출처는 숫자마다가 아니라 **섹션 단위 한 줄**(`SourceChip`).

## 4-1. 유리 층 (Liquid Glass)

애플 iOS 26의 Liquid Glass처럼 **콘텐츠 위에 떠서 움직이는 탐색 층에만** 유리를 쓴다.
데이터는 늘 불투명한 흰 면 위에 있다 — 숫자 뒤로 다른 숫자가 비치면 읽기가 무너진다.

| 쓰는 곳 | 클래스 |
|---|---|
| 상단 헤더, 설문 헤더 | `.glass-bar` (아래 선만) |
| 모바일 하단 탭 막대, 팝오버(계정 메뉴·시장 흔들림 설명) | `.glass` (안쪽 빛 테두리 + 윤곽 + 떠 있는 그림자) |

- 카드·목록·차트·모달 본문에는 쓰지 않는다. 한 화면에 떠 있는 유리는 두 겹을 넘지 않는다.
- 유리 위 글자도 4.5:1 이상. 흰 72% 위에서 `body` 이상 진한 글자만 쓴다.
- 글이 여러 줄인 팝오버(계정 메뉴·시장 흔들림 설명)는 뒤 글자가 비쳐 읽기 어려우므로 흰 90%(`glass bg-white/90`)로 짙게 한다.
- 설명 팝오버는 트리거 바로 아래에 붙는다. 마우스는 올리면·키보드는 포커스가 가면 보이고, 터치는 탭으로 열고 바깥 탭·Esc로 닫는다(`market-detail.tsx`). 헤더의 `backdrop-filter`가 `fixed`의 기준 상자가 되므로 헤더 안에서 띄우는 것은 body로 portal한다.
- `prefers-reduced-transparency`·`prefers-contrast: more`·흐림 미지원 브라우저는 불투명 흰 면으로 바뀐다(`globals.css`).
- 클레이모피즘(부푼 3D)·뉴모피즘은 쓰지 않는다. 장난감처럼 보여 금융 근거의 무게와 맞지 않고, 면 대비가 낮다.

## 5. 모션

- 150~200ms `ease-out`, **펼치기/닫기와 눌림 피드백에만.** 등장 애니메이션·스크롤 연동 없음.
- `transform`·`opacity`만 움직인다. `prefers-reduced-motion`은 `globals.css`에서 전역 처리.

## 6. 차트

- 격자 최소(가로 기준선 하나 정도), **범례 대신 직접 라벨**, 강조점 하나.
- 차트 하나가 질문 하나에 답한다. 두 질문이면 차트를 나눈다(작은 여러 개).

## 7. 이 프로젝트에만 있는 제약

`AGENTS.md`의 표현 규칙이 디자인보다 위다.

- 미래 주가 점선 곡선 금지. 확률 단정 금지.
- 모든 수치에 비교 기준·구간 말·출처가 붙는다. 정리한다고 빼지 않고 접는다.
- **하드 제약**(사용자가 직접 정한 것)은 주의 표시로 칠하지 않는다. 위험이 아니라 사용자의 선택이다.
- 재점검 신호 옆에는 매도 지시가 아니라는 표시가 늘 함께 간다.
- 화면 문구는 `lib/copy-glossary.ts`의 쉬운 말을 쓰고, 금지어는 `lib/copy-rules.ts`가 검사한다.
