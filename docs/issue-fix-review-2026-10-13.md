## 서빙 모델에 문제가 있는가

현재 활성 모델 파일·입력 순서·클래스 매핑·builder 계약의 불일치는 발견되지 않았다. 실제 운영 [실행 38379035619](https://github.com/2026Graduation-Work/take_a_look/actions/runs/38379035619)은 기준일 2026-10-13 게시와 retention·수급·종목 마스터까지 성공했다. 이 성공은 이미 main에 반영된 #285·#291·#306 이후의 결과이며 이번 로컬 수정의 배포 결과가 아니다.

활성 pack은 `kospi_shared_v3_flow_train2023_2025_20261011`, H5(공격형)와 H20(안정형) 모두 수급 포함 170개 입력이다. 압축 SHA-256은 `26fd46a82e18abf20f8fc15510964cb7dd402fa3a8200fa7447899b69540821f`, builder 계약 해시는 `64abc83dce3eb7164c1e94cab75484c757684fce0c56342863dc7b01baca3fed`다. 현재 코드로 `load_pack`을 실행해 모델·과거 사례·달력·builder 원문 해시와 H5/H20·성향·3클래스·피처 순서를 검증했다. 공용 builder와 운영 모델은 수정하지 않았다.

다음 한계는 모델 손상 여부와 별개다.

- 운영 대상 913종목 중 수급 입력이 완전한 종목은 788개다. 125종목은 H5/H20 신호가 모두 미제공이라 1,826개 snapshot 중 250개가 unavailable이다. 수급 조회는 20일 모두 성공했지만 종목별 행 결측이 남는다. 결측을 0으로 채우면 의미가 달라지므로 그렇게 고치지 않았다.
- 학습 범위 밖 28개(리츠·인프라 26개와 외국 주권 2개)는 모델 대상에서 제외한다. 검색·상세 종목 마스터에서 종목을 제거하는 작업은 수행하지 않았다. 리츠까지 신호를 제공하려면 학습 범위와 데이터 정의를 먼저 바꿔야 한다.
- 심리 추가 B(174개 입력)는 연구용 비교 모델이다. 성적표 A도 과거 연도별로 따로 학습한 모델이므로 현재 운영 pack 자체의 과거 검증 성적이라고 표시하지 않는다.
- 2019~2025 연도별 평균 ROC-AUC는 H5 A=0.584627, B=0.584964, 차이 +0.000336이고 H20 A=0.566289, B=0.566721, 차이 +0.000432다. 같은 실험의 독립 연도 수익률 평균 차이는 H5 −0.1665%p, H20 −3.3790%p다. 판별력이 소폭 높아져도 거래 성과 개선을 뜻하지 않는다. 현재 자료만으로 심리 모델로 운영을 전환할 근거는 부족하다.
- 수정가격의 시점·수급 정보 결합 정책·공통 관측 표본의 한계가 남는다. 시간순 OOS지만 연구자가 손대지 않은 최종 holdout이나 통계적 유의성의 증거로 주장하지 않는다.

## #308: 보유 목록 복원과 저장 실패의 데이터 손실

원인: 편집 화면은 localStorage만 읽었고 계정 DB를 읽지 않았다. 저장 함수는 전체 보유를 먼저 비활성화했다. 잘못된 값은 필터로 버리고 모르는 종목은 DB 쓰기 이후 오류로 알려, 화면 조회만 고쳐도 데이터 손실 경로가 남았다.

수정:

- 계정의 활성 `portfolio_holdings`를 DB에서 표시 순서대로 읽어 종목명·수량·평균 매입가를 복원한다. `rows`와 되돌리기 기준 `baseline`을 함께 초기화한다. 데모는 기존 브라우저 저장 경로를 유지한다.
- 조회 중·실패 시 저장과 편집을 막고 재시도를 제공한다. 조회 실패를 빈 보유로 표시하지 않는다.
- 계정별로 편집 컴포넌트를 새로 만들고 오래된 조회 응답을 폐기한다. 조회·저장 후 계정 ID도 다시 확인해 이전 계정 자료를 다른 계정 화면이나 캐시에 반영하지 않는다.
- 입력 전체·중복·종목 마스터 검증을 쓰기 전에 끝낸다. 일부를 조용히 버리지 않는다. 현재 목록 upsert 성공 후 목록에서 빠진 종목만 비활성화한다.
- KRX 영문 포함 6자리 코드도 입력 검증을 통과한다. 실제 등록 가능 여부는 종목 마스터로 확인하므로 임의 종목 코드를 저장하지 않는다.

검증: 단위 테스트로 조회 오류·계정 변경·잘못된 값·알 수 없는 종목·upsert 실패·삭제 순서·빈 목록·계정 변경 후 캐시 쓰기 차단을 확인했다. 브라우저에서 저장본 없는 상태의 DB 복원, 새로고침, 로그아웃→같은 계정 로그인, 저장 실패 시 기존 보유 보존, 조회 실패 중 저장 차단과 재시도를 확인했다.

남은 경계: upsert와 비활성화는 별도 요청이다. 삭제 요청이 실패하면 추가·수정만 반영될 수 있어 오류에 부분 반영과 재조회 안내를 표시한다. 완전한 원자성은 DB 트랜잭션 RPC와 계약 합의가 필요하다. 운영 사이트에는 아직 이 수정이 반영되지 않았다.

## #249: 날짜별 가격 묶기와 replay 오류

피처 하루 한 파일은 main에 이미 구현돼 있었다. 남은 날짜별 가격은 종목마다 별도 파일이었다. 추가로 main의 replay는 피처를 다시 업로드했고, 묶음 피처 파일 읽기는 요청 종목만 선택하지 않았다. 여러 종목이 한 파일을 공유하면 replay가 잘못된 행을 읽거나 실패할 수 있었다.

수정:

- 날짜별 가격을 `raw-prices-v3/<as_of>/batch.parquet`에 묶고 파일 SHA-256·날짜·종목별 원본 입력 해시를 `batch.manifest.json`에 기록한다.
- 읽을 때 파일 SHA·종목/날짜 유일성·기준일·manifest 종목 집합을 확인한다. 요청 종목의 행만 반환하고 원본 입력 해시를 복원한다. 기존 종목별 파일도 읽는다.
- 같은 묶음 파일은 한 실행에서 한 번 읽는다. 옛 날짜의 묶음 파일 부재도 캐시해 종목마다 동일한 실패 요청을 반복하지 않는다.
- 피처 파일도 요청 종목 한 행만 반환하고 날짜·SHA를 검증한다. 재실행은 피처와 입력 파일을 다시 업로드하지 않는다.
- DB 유니버스 조회는 1,000행 단위로 끝까지 읽고 영문 포함 종목 코드를 유지한다.

검증: panel round-trip, 파일 변조 거부, 기존 파일 읽기, 1,001종목 페이지 처리, replay 쓰기 없음, 피처 종목/날짜 불일치 거부를 테스트했다. 실제 10/06 삼성전자 자료와 활성 170개 입력 H5/H20 모델로 저장 전후 점수·입력 내용 해시·기여도가 정확히 같음을 추가 확인했다. 저장 파일의 숫자 dtype 폭과 파일 SHA가 바뀔 수 있으므로 모델 입력 내용·신호 동일성과 파일 무결성 검증을 구분한다.

## #214: 완료된 A/B 자료의 검증과 내보내기

검증: 잘못된 입력 해시·비교 표본·라벨·점수 컬럼·집계 방식의 거부와 미산출 값 유지를 테스트했다. 실제 내보내기 명령과 프론트 빌드도 통과했다.

## #107: 달력 전환 후속

main의 운영 경로는 옛 registry/core/벌크 수집 경로를 대체했다. 달력은 일일 수집당 한 번 받아 공용 builder에 넘기고 달력 계약 실패는 게시를 중단한다. 공급자 가격 부재는 종목별 unavailable로 남으며, 캐시 경로는 CWD에 의존하지 않는다. 옛 캐시 합치기의 NumPy timedelta는 이미 명시적 D 단위다.

이번 수정은 serving의 240일 날짜 계산에도 명시적 D 단위를 사용했다. 달력 캐시 관련 7개 테스트를 DeprecationWarning 오류 모드로 통과했다. 달력 누락·잘못된 범위·replay·게시 계약도 chart 전체 테스트로 검증했다.

경계: 전체 코드에서 DeprecationWarning을 오류로 승격하면 공용 수집 코드의 다른 `pd.Timedelta(days=...)` 경로에서 pandas/NumPy 호환 경고가 남는다. 공용 코드는 운영 pack의 source SHA 계약에 포함돼 이 경고만 없애려고 단독 수정하면 #267처럼 pack 호환이 깨진다. 현재 모델 파일 문제는 아니며, 공용 코드·pack 출처를 같이 갱신하는 후속 호환 작업으로 남긴다.

### PR #313 봇 리뷰 반영

가격 manifest는 기존 버킷 계약의 application/octet-stream으로 저장하고 읽을 때 JSON을 해석한다. 로그인 계정 보유 조회 성공 시 공유 저장소를 동기화한다. 완료 상태와 입력 manifest의 누락 해시는 첫 내보내기 커밋에서 기록된 보조 증거에 고정하고 exporter가 새 해시를 자동 신뢰하지 않는다. A/B의 데이터·피처 구성 계약을 비교하고 작은 ROC-AUC·일치율·Brier·ECE 차이는 6자리로 표시한다. Storage 실측 단계는 retention 바로 뒤로 이동했다.

10/14 확인한 정기 실행 38436318274는 10/13 예약이 지연되어 실행됐으며 KRX HTTP 200 HTML 응답 때문에 가격 재조회에서 중단됐다. serving 읽기에 최대 3회 재시도를 추가했다. 계약 오류는 재시도하지 않고, KRX 오류가 계속되면 게시를 중단해 기존 배치를 보존한다.
