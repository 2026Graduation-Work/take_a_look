# 보안 점검 2026-10 — 최근 금융권 연쇄 해킹을 기준으로

작성일: 2026-10-20. 계기는 10/19 지도교수님 면담 피드백 ⑤입니다. 최근 사고의 공통점 두 가지를 기준으로 봤습니다.

1. **로그인 없이 쓰는 기능과 내부용 기능이 인증 우회로 뚫렸다**(간편조회, 직원용 업무 시스템)
2. **늦게 알았다**(침입부터 탐지까지 15~67시간)

앞선 점검은 `docs/security.md`(2026-10-06)입니다. 이 문서는 그 뒤 상태를 실제로 시험한 결과입니다.

**요약: 비밀키 노출 없음. 남의 데이터를 읽거나 쓸 수 있는 경로 없음.** 고친 것은 CSP 전체 적용, 개발용 경로 404, 뷰 쓰기 권한 회수, 의존성 1건, 서드파티 액션 SHA 고정, 주간 감시에 RLS·가입 수 검사 추가입니다. 대시보드에서 사람이 바꿀 것 3가지는 맨 아래에 있습니다.

## 1. 데이터 접근 (RLS)

**확인 방법**: `supabase db query --linked`로 `pg_class.relrowsecurity`, `pg_policies`, 권한 표를 읽고, 실제 접근은 `BEGIN … ROLLBACK` 안에서 `set local role anon|authenticated` + `request.jwt.claims`(다른 사용자 `sub`)로 바꿔 시험했습니다. 운영 데이터는 바뀌지 않았습니다(전부 rollback). 대조군으로 피해자 본인 토큰은 보유 3건, users 1건이 보였습니다.

**테이블별 RLS와 정책** (public, 2026-10-20)

| 테이블 | RLS | 익명(anon) | 로그인 사용자 |
|---|---|---|---|
| `users` | 켜짐 | 권한 없음 | 본인 행 select, insert, update(`auth.uid() = auth_user_id`) |
| `ips_profiles`, `portfolio_holdings`, `watchlist`, `avoided_assets` | 켜짐 | 권한 없음 | 본인 행 select, insert, update(users를 거쳐 `auth.uid()` 확인) |
| `stock_notes` | 켜짐 | 권한 없음 | 본인 행 전부(ALL) |
| `stocks`, `market_status`, `supply_demand`, `disclosures`, `financial_*`, `news_*`, `predictions`, `prediction_features` | 켜짐 | select만 | select만 |
| `chart_batches`, `chart_releases`, `chart_signal_snapshots` | 켜짐 | 게시된 배치만 select | 같음 |
| `chart_prices`, `chart_feature_snapshots`, `chart_prediction_log`, `chart_universe` | 켜짐 | 정책 없음(거부) | 정책 없음(거부) |
| `latest_chart_signal_snapshots`(뷰) | `security_invoker=true` | select(+ 기본 쓰기 권한이 붙어 있었음) | 같음 |

**시험 결과**

| 시도 | 익명 | 다른 사용자 |
|---|---|---|
| 피해자 보유, 성향, 관심, 메모, 회피 항목, users 읽기 | 거부(42501) | 0건 |
| 피해자 보유 추가, 메모 추가 | 거부 | 거부(42501, 정책 위반) |
| 피해자 보유 수정, 메모 삭제, users 행 가로채기(`auth_user_id` 변경) | 거부 | 0건 |
| 공개 테이블(`stocks`) 수정 | 거부 | 거부 |
| 관리 함수 `budget_usage()` 호출 | 거부 | 거부 |

- 데모 계정: Supabase 계정이 아니라 브라우저 저장(`localStorage`)입니다. 공용 데모 데이터를 남이 바꾸는 경로가 없습니다.
- **조치**: 뷰 `latest_chart_signal_snapshots`에 Supabase 기본 권한으로 붙은 INSERT, UPDATE, DELETE, TRUNCATE를 거두고 SELECT만 남김(`0015_security_watch.sql`). 뷰가 조인과 LIMIT이 있어 원래도 쓸 수 없었지만 권한 표에서도 읽기만 보이게 했습니다.

**security definer 함수**

| 함수 | 실행 가능 |
|---|---|
| `delete_my_account()` | authenticated(본인 계정만 지움, 0008) |
| `publish_chart_batch`, `withdraw_chart_batch`, `prune_chart_batches`, `log_chart_predictions`, `guard_chart_snapshot_stage`, `budget_usage` | service_role만 |

## 6. 보안 헤더

| 헤더 | 전 | 후 |
|---|---|---|
| CSP | `frame-ancestors 'none'`만 | `default-src 'self'`, 스크립트는 자기 출처 + 인라인(Next), 연결은 Supabase만(모든 화면 같음). 글자 읽기 워커 파일(`/ocr/`) 응답에만 `'unsafe-eval'`(OpenCV가 `new Function` 사용), 화면에는 없음 |
| frame-ancestors, X-Frame-Options | 있음 | 유지 |
| Referrer-Policy | `strict-origin-when-cross-origin` | 유지 |
| Permissions-Policy | camera, microphone, geolocation 차단 | + payment, usb |
| X-Content-Type-Options | nosniff | 유지 |
| HSTS | Vercel 기본(2년, preload) | 유지 |

- 확인: 로컬 운영 빌드에서 데모로 대시보드, 종목 상세, 성적표, 성향 화면을 열어 콘솔 CSP 위반 0건, `/portfolio`에서 실제 글자 읽기 성공(첫 실행 약 50초, 24.9MB).

## 9. 탐지

- 주간 감시(`free-tier-watch.yml`, 월 10:07)가 읽는 `budget_usage()`에 세 값을 더했습니다(`0015_security_watch.sql`).
  - `rls_disabled_tables`: RLS가 꺼진 public 테이블 이름. **하나라도 있으면 작업이 실패**하고 `[ops] 보안 감시 경고` 이슈를 엽니다(실패 알림 메일도 감).
  - `signups_24h`, `signups_7d`: 새 가입 수. 매주 로그에 남기고, 7일 50건을 넘으면 경고.
- 수동 시험용 `dry_run` 입력: 이슈는 남기지 않고 측정과 실패 여부만 봅니다.
- 남은 위험: 주 1회라 최악의 경우 7일 늦게 압니다. 매일로 바꾸면 Actions 무료 시간 안이지만, 지금 규모(사용자 3명)에서는 주 1회로 둡니다.

## 중현이 대시보드에서 할 일

1. Supabase → Authentication → Sign In / Providers → Email → **Minimum password length 8** → Save. (화면 안내는 이미 8자)
2. 시연 기간이 끝나면 같은 화면에서 **Confirm email 켜기**. 켜기 전에 `docs/auth-setup.md` 3-2의 메일 한도(시간당 2통)를 확인합니다.
3. 주간 감시 이슈에 가입 수 경고가 오면 Authentication → Attack Protection → **CAPTCHA 켜기**(Cloudflare Turnstile 무료, 사이트 키는 Vercel 환경변수로).
