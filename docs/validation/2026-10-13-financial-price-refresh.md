# PER·PBR 주가 갱신 분리 — 로컬 검증

브랜치: `fix/financial-price-refresh`. 네이버 전환·재무 대상 목록 변경은 포함하지 않는다.

- 주간 연간 보고서 수집은 같은 접수번호여도 새 가격 기준을 저장한다.
- 가격은 실제 마지막 거래일을 기록한다. 같은 보고서의 가격·주식수 조회 실패는 기존 스냅샷을 보존한다.
- 재무 조회 시 저장된 PER·PBR에 최신 차트 가격비를 적용한다. ROE 등 다른 4개 지표와 보고서 기준은 유지한다.
- 가격비의 분모는 최신 차트 이력에서 찾은 원래 기준일의 수정종가다. 액면분할 전후 가격 단위를 맞춘다.
- 비교 날짜가 이력에 없거나 새 가격이 없거나 오래된 경우는 저장된 값·가격 기준일을 유지한다.
- 매 조회는 원본 DB 비율에서 시작해 반올림 오차를 누적하지 않는다. 원본 비율 소수점 4자리의 정밀도 한계가 있다.
- 적자 PER·결측 값을 가격으로 채우지 않는다. 가격 조회 오류도 재무표 전체를 숨기지 않는다.
- DB·schema 계약 변경, 유료 API 추가, 운영 데이터 적재는 없다.

## 확인

- 회귀 테스트: 동일 보고서 가격 변화, 다른 재무 지표 유지, 적자 PER, 가격 결측·오류·0·무한값·잘못된 날짜·동일/오래된 날짜, 액면분할, 수정 가격 기준 부재.
- Python 회귀: 같은 공시 재수집의 가격 기준 갱신, 가격·주식수 실패 보존, 휴장일의 실제 거래일·미래 가격 제외.
- 프론트 단위 테스트 117개, 텍스트 Python 테스트 171개, 변경 파일 ESLint와 텍스트 ruff, 프론트 프로덕션 빌드 검증.
- 로컬 화면 `http://127.0.0.1:3103/stocks/005930` → 회사 체력 → 계산 근거.
  테스트 데이터: 주가 10,000원(10/07) → 12,000원(10/13), PER 10 → 12배, PBR 2 → 2.4배, ROE 8%·부채비율 60% 유지.
  2025년 연간 재무와 두 가격 기준일을 근거에 표시한다. 다른 탭의 운영 상태를 재현하는 서버는 아니다.

운영 적용 전 사용자가 로컬 화면을 검토한다. push·PR·머지·배포는 실행하지 않았다.
