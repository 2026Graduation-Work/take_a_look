# 수급 수집 실패 원인과 수정 결과 (2026-10-07)

기존 `local_2016_v1`의 2,637일 수급 캐시를 다시 검증했다. 날짜·종목 코드·중복·음수/무한대·파일 해시/검증 버전 검사에서 실패는 0건이다. 이번 전체 구축 실패는 수급 요청 실패가 아니라, 종목별 결측까지 모두 없어야 한다는 완료 조건과 별도의 가격 검증 실패가 함께 발생한 결과다.

## 원인 확인

수집기는 `pykrx.get_market_net_purchases_of_equities_by_ticker`를 사용한다. 설치된 구현은 KRX **투자자별 순매수상위종목** `MDCSTAT02401` 응답을 가져온다. 종목별 완전한 거래실적 목록이라는 보장은 없다. 세 투자자 응답의 종목 인덱스를 합치므로 특정 투자자 응답에 종목이 없으면 해당 투자자의 네 값이 결측이 된다.

실제 재조회 사례: 2016-01-04, `101930`.

- 기관합계 순매수상위종목 응답 1,348행에 해당 코드가 없다. 기존 캐시도 기관합계 네 열이 모두 결측이다.
- 같은 날짜·종목의 개별 거래량 응답은 기관합계 매수량 0, 매도량 0을 명시한다.
- 따라서 이 사례는 요청 실패나 병합 중 값 유실이 아니라, 사용한 목록에서 종목이 생략된 사례다. 다른 모든 결측이 같은 원인이라는 뜻은 아니다.
- 2026-04-10의 같은 종목은 원천 거래량·거래대금이 0이며 일별 수급 목록에도 없다. 거래 없는 날짜의 결측도 완전성 조건을 실패시키고 있었다.

이 확인만으로 나머지 결측을 0으로 채우지 않는다. 현재 합의대로 결측을 유지한다. 향후 별도 원천으로 복구하려면 해당 날짜·투자자의 명시적 매수/매도 거래량과 대금을 모두 확인해야 한다. 특히 개별 조회의 `외국인합계`와 현재 `외국인`은 집계 대상이 같다고 가정하면 안 된다.

## 실행한 해결 순서

1. 날짜별 조회 검증 성공(`flow_queries_complete`)과 모든 종목 원천 관측의 완전성(`flows_complete`)을 분리했다. 가격 성공은 `prices_complete`로 독립한다. 수급 조회 실패나 결측 때문에 정상 가격 구축을 실패시키지 않고 조회 실패 날짜는 별도 보고한다.
2. 응답에 없는 관측은 결측으로 보존했다. 부분 문자열·음수·무한대·잘못된 날짜·중복 코드는 유효 관측으로 받아들이지 않는다.
3. 기존 1/5/20 시장 거래일 피처의 완전한 창 조건을 유지했다. 실험에서 선택한 수급 대금 피처가 모두 있는 표본만 포함한다. `flow_excluded_rows`는 기본 조건을 통과한 표본 중 수급 때문에 제외된 수다.
4. `--verify-flows`로 가격 재다운로드 없이 기존 수급 캐시 전체를 재검증하고, `flow_validation_report.json`에 투자자별 관측·창 커버리지를 저장했다.
5. 실제 2016-01-04 응답 생략과 유한양행 2016-01-07~08 수정 OHLC 오류를 회귀 검증 자료에 기록했다. 부분 수급과 요청 실패에도 기본 전처리가 가능한 테스트를 추가했다.

## 2026-10-08 KOSPI 완료 단계 실패

수급 일별 요청 실패는 0건이었고, 1,013종목 병합까지 끝났다. 최종 실패 원인은 가격 6종목의 각 하루에 KRX 원천 시가·고가·저가가 모두 0인데 거래량·거래대금은 양수인 관측이었다.

- 001527: 2024-03-28, 거래량 2, 거래대금 23,060원
- 015540: 2016-03-25, 거래량 5,161, 거래대금 8,773,700원
- 016380: 2016-02-16, 거래량 437, 거래대금 1,092,500원
- 016385: 2016-02-16, 거래량 131, 거래대금 474,220원
- 047810: 2017-10-11, 거래량 141, 거래대금 6,725,700원
- 145210: 2025-03-21, 거래량 1,015, 거래대금 1,142,890원

양수 거래량만으로 정규장 OHLC가 존재한다고 가정한 검증이 잘못되었다. 정규장 미체결과 공식 거래정지는 구별해야 한다. 일부 날짜의 거래정지 사실이 확인돼도 6건 전체를 거래정지나 특정 시간외 거래로 단정하지 않는다.

원천 OHL 세 값이 **모두 정확히 0**인 행에만 `RegularSessionUnavailable`을 기록한다. 원본 OHL·종가·거래량·거래대금과 동일 수정계수, 실제 대금/거래량 VWAP을 보존한다. 일부 값만 0, 음수, NaN, 무한대인 정상 거래 행은 여전히 실패한다. 양수 거래량 행의 양수 종가·대금·수정계수, VWAP 산식과 동일 계수 적용 검증도 유지한다. 존재하지 않는 정규장 범위와 VWAP은 비교하지 않고 해당 날짜를 별도 품질 보고한다.

전처리에서 이 행은 기존 `Trading_Halt` 실행 제외 경로를 사용한다. 이 필드는 전처리 이후 학습 표본·레이블 진입·백테스트 체결 제외를 뜻하며, 공식 거래정지 공시를 확인했다는 뜻은 아니다. 피처용 OHLC/VWAP은 종가, Volume은 0으로 정규화하되, raw 파일과 `RawVolume`, `Amount`는 보존한다. 수급 원천도 0으로 채우지 않는다. 거래량이 양수인 정규장 미관측 날짜는 `collection_report.json`의 종목별 `regular_session_unavailable_dates`에서 확인한다.

실제 6건을 회귀 자료에 추가했다. 정상 완료 종목과 2,637일 가격·수급 캐시는 재사용하고 `--rebuild` 없이 실패 종목만 재개한다.

수정 후 기존 KOSPI raw 1,013종목을 검증해 재사용하고 6종목의 가격을 보완했다. 실제 raw 파일을 다시 읽어 6건 모두 원천 거래량·대금·VWAP 산식 보존과 전처리 실행 제외 플래그를 확인했다. 관련 테스트 91개 및 Ruff를 통과했고, 보완 후 VWAP 완전성 검사를 포함한 회귀 테스트 17개도 통과했다.

재개 결과 `collection_report.json`은 `status: complete`, `prices_complete: true`, `flow_queries_complete: true`다. 기존 1,013종목 재사용, 6종목 가격 보완으로 총 1,019종목이고 가격 실패·수급 조회 실패는 각각 0건이다. 수급 캐시 2,637일을 모두 재사용했다. `flows_complete: false`는 원천 목록에 없는 수급 결측이 보존됐다는 뜻이며, 기본 모델 실행을 막지 않는다. 수집 성공을 조건으로 연결한 쉘이 KOSPI 전처리를 시작했다.

사용자가 후속 스크립트를 직접 실행하겠다고 요청하여 자동으로 시작된 전처리 프로세스와 쉘을 중단했다. 수집 완료 결과와 이미 저장된 출력은 보존했다.

## 2026-10-08 백테스트 체결·상폐 오류 수정

합의에 따라 수정가격 기준 주문 수량을 정수 버림하고, 수수료 포함 예산으로 1단위도 살 수 없으면 주문을 건너뛴다. 확인된 상폐일부터는 평가액·회수 현금 0원 가정을 적용한다. 실제 매도 주문은 만들지 않으며, 손실은 별도 writeoff 기록과 종료 거래 손익 통계에 포함한다. 일반 보유 가격 누락은 여전히 실패한다.

실패했던 실제 연도를 기존 예측·가격으로 재현해 모두 통과했다. 이 검증은 저장된 백테스트 결과를 갱신하지 않았다.

- H5 수급, 2019년: 현금 부족 오류 해소, 정수 매수 110건.
- H20 기본, 2022년: KG스틸우(016385)의 2022-07-15 상폐 평가손실 처리, 정수 매수 70건.
- H5 기본, 2023년: SK네트웍스우(001745)와 추가로 보유하게 된 현대비앤지스틸우(004565)의 2023-07-17 상폐 평가손실 처리, 정수 매수 53건.

체결 정책·기존 계약 테스트 40개와 Ruff를 통과했다. 수수료 포함 손실이므로 상폐 거래 Return은 원금 대비 -100%보다 작을 수 있다. 비교를 통일하려면 기존에 성공했던 H20 수급도 포함해 네 백테스트를 다시 실행한다. 명령은 LOCAL_PIPELINE.md의 주문 수량·상폐 정책 절에 있다.
